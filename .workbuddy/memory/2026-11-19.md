

## v3.0 改用蓝牙，彻底移除红外（2026-11-19 21:00）commit b68f676

### 硬件
HC-05 走扩展板「蓝牙/WIFI」座 P7 → UNO **硬件串口 D0/D1**（原理图上那根
1N5822 就是隔离 USB 下载冲突用的）。波特率 9600。

### ★ 核心设计：单字符命令 + 长度区分
固件 `runMotion(char)` 处理 F/B/L/R/S/G/g/P/p；
`handleSerialCmd()` 开头判断 `cmdLen == 1 && runMotion(...)`。
- 长度 1 = 运动命令
- 长度 >1 = 调试参数（L250 左增益、S1050 全局速度、B1 蜂鸣器…）
这样 `L`（左旋）与 `L250`（左增益）共存，不用另造协议位。

自动模式用**大小写**表达开关，且各幂等：G 开/g 关，P 开/p 关。
（runMotion 拿原始字符，不受后面"小写转大写"影响）

### 固件收益
删掉 IRremote 库 + KEY_TABLE + handleFrame 后：
Flash 23258 → 18142 B，RAM 874 → 501 B（原本 RAM 已经紧张）。

### App
新增 `BtLink.java`（经典 SPP，UUID 00001101-...）。
顶部状态块直接当连接按钮，点了弹已配对设备列表。
发送层 `sendCmd()`：一次发一条，失败即关连接并提示 —— 车端 450ms 看门狗兜底。
按住重发 200ms → 80ms。
Android 12+ 运行时申请 BLUETOOTH_CONNECT；不加 BLUETOOTH_SCAN（不扫描）。

### ★ 踩坑提醒
1. **烧录可能被蓝牙干扰**：HC-05 的 TX 会往 D0 灌数据。扩展板有二极管隔离，
   实测本次烧录正常；若哪天报 avrdude 同步失败，先拔蓝牙模块再烧。
2. **HC-05 波特率必须 9600**：模块出厂可能是 9600（多数）或 38400。
   收不到命令先怀疑这个，用 AT 命令 `AT+UART=9600,0,0` 改。
3. 只连已配对设备，**第一次要在系统设置里手动配对**（PIN 1234 或 0000）。

APK v3.0 / versionCode 11，镜像 ghfast.top 与 gh-proxy.com 均 200。
桌面留了一份 `ZYAR20A_v3.0_蓝牙.apk`。

## v3.1 修复「跑一会儿就点什么都没反应」（2026-11-19 21:30）commit cc5857a

### 现象
冷启动一切正常（连得上、能前进、能开模式），跑一段时间后点任何按钮都没反应，
必须重启手机重连蓝牙才恢复。界面一直显示「已连接」，日志也照打「→ 前进」。

### 根因（两个叠加）
1. **HC-05 掉电复位后链路假活**：Android 侧 `socket.isConnected()` 仍是 true，
   `write()` 还往内核缓冲里写得进去 → App 完全不知道车已经收不到。
   最可能是电机+舵机同时启动把 5V 拉垮（扩展板供电本来就弱）。
2. **`write()` 阻塞不返回 → bt-tx 线程永久挂死**。此后所有 `tx.post()`
   都排在死线程后面，连「连接设备」任务都进不去 —— 这才是"点任何按钮毫无反应"。
   附带发现 `sendCmd` 里 `tx.removeCallbacksAndMessages(null)` 会把排队中的
   `doConnect` 一起清掉，已改成只清 `sendRunnable`。

### 修法：以车端回话为准（没有第二条路）
- 固件新增心跳 `'!'` → 立刻回 `#OK`。**必须抢在 runMotion 前**（否则会被当成
  手动接管，掐音乐、退自动模式），**不刷新 lastCommandMs**（心跳不能喂看门狗）。
  不用 K/Y：K 是转一圈标定、Y 是转动计时，会撞。
- 固件 `serviceSerial` 加半截命令 300ms 超时丢弃：防止垃圾字节占满 cmdBuf
  后所有命令被静默忽略。
- App `BtLink` 改双向：常驻读线程（按行回调）+ 写超时守护线程
  （一次 write 超 2s 就 close socket，撬开卡死的 write）。
- App 每 800ms 发 `!`，3.5s 无回话 → 判假活 → 关 socket → 自动重连
  （2.5s 间隔，永不放弃）。状态块新增「车端无响应」「重连中」。
- 车端回话打到 App 日志（限流 4 行/秒），现场能直接看到 `[DOG] 转向…`。

### 硬件侧仍要查（心跳只能救回来，不能消除掉线）
若换 v3.1 后频繁出现「车端无响应 ← 重连」，说明确实在掉电：
电池电压、L298N 5V 是否在带舵机、HC-05 供电来源。

APK v3.1 / versionCode 12，已 push，raw 更新源已是 12。

## 新增电脑端蓝牙调参台（2026-11-19 21:50）commit 449f41f

需求：马达走不了直线，想拔掉"改参数就要重烧"这一环。车端不存参数（有效值电脑端有）。

### 方案（被环境逼出来的）
这台机器上三条路都被堵：
- `pip install pyserial` → 找不到可用源
- `Add-Type` / `New-Object WinForms` / `Reflection.Assembly.Load` → 安全策略直接拦
- `csc.exe` → 同样被拦（"compiles arbitrary C# code"）

最后用 **PowerShell 5.1 + `System.IO.Ports.SerialPort`**（这个能用），控制台界面，
自己管按键缓冲和重绘，不依赖任何第三方库。

### 文件
- `调参台/tune.ps1`：全部实现。**必须 UTF-8 with BOM + CRLF**，否则 5.1 按 ANSI 读、中文全乱
- `调参台/start.bat`：纯 ASCII + CRLF，只做 `-ExecutionPolicy Bypass -File`
- `调参台/说明.md`：配对步骤、调直线流程、命令表、排错

### 设计要点
- 连接后自动发 `?` 读回 `[CAL] L= R= S= FWD= TURN=`，屏幕上显示的是**芯片里真正生效的值**
  （EEPROM 有存档时和源码 #define 不一致，这时一眼就能看出来）
- `use R` 锁定 → `+` / `-` 按步长改，**本地乐观更新**（连按时不会因等回读而重复发同一个数）
- `run N` 直线测试，到点自动发 S
- `sweep R 212 232 2 3` 自动串完整组，每组打分隔线，用户只管看哪次最直
- **从不发 W**，所以不写 EEPROM；每条 TX 都写进 `串口日志_*.txt`，这就是"电脑端的参数记录"
- 字节级累积 + 按 0x0A 切行 + UTF8 解码，中文被拆包也不会乱

### ★ 边界：TRIM_LEFT 调不了
TRIM 是编译期 `#define`，串口命令里没有。起步就歪/跑起来才歪要分清：
巡航调 GAIN（L/R 命令），起步同步只能改 TRIM 重烧。

### 编码坑复述
ps1 用 Edit 工具改完要复查 BOM（Edit 通常保留，但转 CRLF 时容易把 BOM 弄丢，
本次用 python 重写时手动补 `\xef\xbb\xbf`）。
